                    1. SECURITY & AUTHENTICATION
================================================================================

WHAT IT IS:
Your account is secured with Supabase authentication. This means your login
credentials are encrypted and stored safely. You can only access your own
projects and projects you've been invited to collaborate on.

HOW IT WORKS:
- Sign up with your email and create a password (minimum 6 characters)
- Log in to access your dashboard
- Your session is automatically saved, so you stay logged in
- If you try to access a project you don't own or aren't invited to, you'll be
  blocked automatically
- All API requests check your identity before allowing any actions

WHAT YOU CAN DO:
- Create an account and log in securely
- Update your profile picture (stored in Supabase Storage)
- Change your display name
- Log out when you're done

SECURITY FEATURES:
- All passwords are hashed (never stored in plain text)
- Projects are isolated per user - you can't see other people's projects
- Collaborators must be explicitly invited
- All data transmission uses HTTPS (encrypted)

                       2. PROJECT MANAGEMENT
================================================================================

WHAT IT IS:
Projects are containers for your research work. Each project holds your code,
datasets, plots, messages, and collaboration settings. Think of it like a
folder for a specific research question or analysis.

HOW IT WORKS:
- Create a new project from the dashboard
- Give it a name and description
- Choose if it's a regular project or NIST-compliant project
- Each project has its own workspace where you work
- Projects are saved automatically as you work

WHAT YOU CAN DO:
- Create unlimited projects
- Name your projects (must be unique per user)
- Add descriptions to remember what each project is about
- Edit project name and description later
- Delete projects you no longer need
- Search for projects by name
- Filter projects: Show all, NIST-only, or Regular-only
- See when projects were last updated
- View projects you own and projects you're collaborating on

PROJECT TYPES:
- Regular Projects: Standard data analysis projects
- NIST-Compliant Projects: Projects that follow NIST SP 800-53 security
  standards (see section 3 for details)

================================================================================
              3. NIST COMPLIANCE MODE vs REGULAR MODE
================================================================================

WHAT IT IS:
NIST (National Institute of Standards and Technology) compliance mode is a
special security mode for projects that handle sensitive data, especially
Protected Health Information (PHI) like patient records, medical data, etc.

REGULAR MODE:
- Standard data analysis projects
- No special security requirements
- Data can be sent to AI models as-is (or randomized for privacy)
- No compliance warnings or special protocols
- Faster workflow for non-sensitive data

NIST COMPLIANCE MODE:
- Designed for healthcare, research, and sensitive data projects
- Requires you to acknowledge 4 compliance requirements before entering:
  1. PHI Handling: System auto-detects and redacts PHI (names, DOB, SSN, etc.)
     You must verify all sensitive fields are properly redacted
  2. Audit & Logging: All uploads, AI interactions, and accesses are logged
     for compliance tracking
  3. Encryption & Transmission: Data encrypted in transit (TLS 1.3) and at
     rest (AES-256)
  4. Legal Responsibility: YOU are solely responsible for compliance. Platform
     makes no guarantees and assumes no liability
- Shows a shield badge on the dashboard
- Automatically includes context window in AI requests
- Routes to special NIST-aware AI agent that understands compliance needs
- PHI columns are automatically detected and redacted before storage
- Original sensitive data is never stored - only redacted versions

WHEN TO USE NIST MODE:
- Working with patient data, medical records, or healthcare information
- Research projects requiring HIPAA compliance
- Any project handling personally identifiable information (PII)
- When you need audit trails for compliance reporting

WHEN TO USE REGULAR MODE:
- Public datasets, anonymized data, or non-sensitive research
- Learning projects, tutorials, or practice analyses
- When you don't need compliance tracking or special security measures

KEY DIFFERENCES:
- NIST projects show compliance modal on first open (must acknowledge)
- NIST projects automatically generate and use context windows
- NIST projects route to compliance-aware AI agent
- NIST projects have PHI redaction built-in
- Regular projects have simpler, faster workflow

================================================================================
                     4. FILE UPLOAD & STORAGE
================================================================================

WHAT IT IS:
You can upload CSV files (comma-separated values) containing your data. These
files are processed and can be used for analysis, visualization, and AI code
generation.

HOW IT WORKS:
- Click the upload button in the workspace
- Select one or multiple CSV files from your computer
- Files are read and parsed automatically
- For NIST projects, files go through PHI detection and redaction
- File metadata (name, size) is saved to the project
- Actual file content is stored in the project's dataset field
- Files can be included or excluded from AI chat and code execution

WHAT YOU CAN DO:
- Upload multiple CSV files to a project
- See file names, sizes, and status in the datasets panel
- Toggle whether each file is included in AI chat
- Toggle whether each file is included when running code
- Remove files from the project
- Preview file data before using it
- For NIST projects: Review redacted data before confirming

FILE STORAGE:
- Files are stored in Supabase database (in the project's dataset field)
- File metadata is saved so you can see what files you've uploaded
- Original files are not stored separately - content is embedded in project
- For NIST projects, only redacted versions are stored (original never saved)

FILE LIMITATIONS:
- Currently supports CSV format
- File size limits depend on Supabase database limits
- Large files may take longer to process

SHARED DATASETS:
- Collaborators can share datasets with the project
- Shared datasets appear in a separate section
- You can choose to include/exclude shared datasets in your analysis
- Each collaborator's shared datasets are tracked separately

================================================================================
                5. AI CODE GENERATION & ANALYSIS
================================================================================

WHAT IT IS:
The AI helps you generate R code for data analysis and visualization. You can
ask questions in plain English, and the AI will create R code that you can
run. The AI understands your data, your project context, and can help with
both creating new code and fixing existing code.

HOW IT WORKS:
- Type your question or request in the chat box
- Select which mode you want: Legacy, Quick, or Ask Data
- Choose which datasets to include (if any)
- AI processes your request along with your data and existing code
- AI returns R code, explanations, plot descriptions, and suggestions

THREE AI MODES:

1. LEGACY MODE:
   - Original code generation mode
   - Embeds CSV data directly in the prompt
   - Good for simple, straightforward code generation
   - Returns R code that you can run

2. QUICK MODE (Recommended):
   - Optimized for faster responses
   - Better structured data handling
   - Includes conversation history for context
   - Supports multiple CSV files
   - Returns R code with metadata (explanations, suggestions)

3. ASK DATA MODE:
   - For asking questions about your data (not generating code)
   - Returns analysis, insights, and suggestions
   - No R code returned (just answers to your questions)
   - Great for understanding your data before writing code
   - For NIST projects: Automatically includes context window

WHAT THE AI RETURNS:
- R Code: Complete, runnable R code with all necessary libraries
- Explanation: Detailed explanation of what the code does
- Plot Description: Description of what visualizations will show
- Next Suggestions: Follow-up questions or analyses you might want to try

AI FEATURES:
- Understands your existing code and can modify it
- Remembers conversation history within a session
- Can work with multiple datasets at once
- Respects privacy mode (uses randomized data when enabled)
- For NIST projects: Uses compliance-aware routing

PRIVACY MODE:
- When enabled, data is randomized before sending to AI
- AI sees structure but not real values
- Protects sensitive data while still allowing code generation
- You can toggle this on/off per request

CONTEXT WINDOW (NIST Projects):
- Automatically generated from your datasets
- Includes study type, objectives, key fields, analysis preferences
- Helps AI understand your research context
- Only used in NIST-compliant projects

- Edit locks prevent conflicts

CODE SELECTION:

                7. TERMINAL VIEW & CODE EXECUTION
================================================================================

WHAT IT IS:
The terminal shows the output when you run your R code. It displays both
standard output (stdout) and error messages (stderr) from your R execution.

HOW IT WORKS:
- Click the "Run" button to execute your R code
- Code is sent to HuggingFace Space (R execution environment)
- Terminal shows real-time output as code runs
- Output is saved to the project for later viewing
- Terminal output persists even after closing the workspace

WHAT YOU CAN DO:
- Run your R code and see results
- View error messages if code fails
- See data processing progress
- View plot generation status
- Scroll through terminal history
- Terminal output is saved automatically

TERMINAL FEATURES:
- Separate display for standard output (green text) and errors (red text)
- Scrollable history
- View-only (you can't type commands directly)
- Shows "Linked" status when real-time collaboration is active
- Activity indicator shows when code is running

CODE EXECUTION:
- Runs on external HuggingFace Space
- Supports full R environment with common packages
- Generates plots that are automatically displayed
- Terminal output is captured and stored

EXECUTION STATUS:
- Shows loading indicator while code runs
- Displays estimated time remaining
- Shows elapsed time for long-running code
- Error messages are clearly marked in red

================================================================================
                     9. COLLABORATION FEATURES
================================================================================

WHAT IT IS:
You can invite other users to collaborate on your projects. Collaborators can
have different permission levels: view-only, edit, or owner.

HOW IT WORKS:
- Project owner invites users by email or user ID
- Invitation is sent and appears in collaborator's dashboard
- Collaborator accepts or declines the invitation
- Once accepted, collaborator can access the project based on their role

WHAT YOU CAN DO:
- Invite collaborators by email address
- Invite collaborators by searching for their username
- Set collaborator role: Edit or View
- Add a message with the invitation
- See list of all collaborators (owner + invited users)
- Remove collaborators
- See collaboration requests you've received
- Accept or decline collaboration requests

COLLABORATOR ROLES:

1. OWNER:
   - Full control over the project
   - Can edit, delete, invite others, manage collaborators
   - Only one owner per project (the creator)

2. EDIT:
   - Can edit code, run code, upload files, chat with AI
   - Can save code versions
   - Cannot delete project or manage collaborators
   - Can share datasets with the project

3. VIEW:
   - Can view code, plots, messages, and terminal output
   - Cannot edit anything
   - Cannot run code or upload files
   - Read-only access

COLLABORATION FEATURES:
- Real-time collaboration panel showing active users
- See who's viewing the workspace
- Collaboration requests appear in dashboard
- User avatars and names displayed
- Activity indicators show when others are active

INVITATION PROCESS:
1. Owner clicks "Invite Collaborator"
2. Enters email or searches for user
3. Selects role (Edit or View)
4. Optionally adds a message
5. Invitation is sent
6. Collaborator sees request in their dashboard
7. Collaborator accepts or declines
8. If accepted, collaborator gains access based on role

              10. VERSION HISTORY & CODE SNAPSHOTS
================================================================================

WHAT IT IS:
Version history lets you save snapshots of your code at different points in
time. You can go back to previous versions, see what changed, and restore old
code if needed.

HOW IT WORKS:
- Click "Save Version" to create a snapshot
- Add a description to remember what this version does
- Versions are saved with code, plots, and timestamp
- You can browse all versions and restore any one

WHAT YOU CAN DO:
- Save current code as a new version
- Add descriptions to versions (e.g., "Added regression analysis")
- View all saved versions in a timeline
- See code differences between versions
- View plots associated with each version
- Restore a previous version (replaces current code)
- Expand/collapse version details
- See who created each version (if collaborating)

VERSION FEATURES:
- Chronological list of all versions
- Version numbers (auto-incremented)
- Creation date and time
- Creator name and avatar
- Code preview for each version
- Plot gallery for each version
- Expandable details view
- One-click restore

VERSION MANAGEMENT:
- Versions are never deleted (for audit trail)
- Each version is a complete snapshot
- Restoring a version doesn't delete newer versions
- You can create new versions from restored code

USE CASES:
- Save working code before making experimental changes
- Track progress on a complex analysis
- Revert to a previous working version if something breaks
- Document major milestones in your research
- Share specific versions with collaborators

             12. CONTEXT WINDOW (NIST Projects Only)
================================================================================

WHAT IT IS:
The context window is a structured description of your research project that
helps the AI understand your study better. It's automatically generated for
NIST-compliant projects and included in all AI requests.

HOW IT WORKS:
- For NIST projects, context window is generated from your datasets
- AI analyzes your CSV files and creates a structured context
- Context includes: study type, objectives, key fields, analysis preferences
- Context is saved with the project
- Automatically included in all AI requests for that project

WHAT IT CONTAINS:
- Study Type: What kind of research (e.g., Clinical trial, Observational study)
- Research Objective: What you're trying to learn or prove
- Dataset Key Fields: Important columns in your data
- Excluded Fields: Fields that won't be shared with AI (PHI protection)
- Preferred Analysis Types: Types of analyses you want to perform
- Additional Notes: Any other relevant information

WHAT YOU CAN DO:
- View the context window for your NIST project
- Edit context fields manually
- Regenerate context from datasets (AI-powered)
- See which fields are excluded from AI sharing
- Add or remove excluded fields
- Update study objectives and preferences

CONTEXT WINDOW MODAL:
- Opens when you click "Context Window" button
- Shows all context fields in a structured form
- AI can auto-generate context from your data
- You can manually edit any field
- Saves automatically when you confirm

BENEFITS:
- AI understands your research goals better
- More relevant code suggestions
- Better analysis recommendations
- Compliance-aware responses
- Consistent context across all AI interactions

                 13. PRIVACY & DATA PROTECTION
================================================================================

WHAT IT IS:
Privacy features protect sensitive data when working with AI models. You can
choose to randomize data before sending it to AI, and NIST projects have
automatic PHI detection and redaction.

PRIVACY MODE:
- Toggle on/off for each AI request
- When ON: Data values are randomized before sending to AI
- AI sees data structure but not real values
- Protects sensitive information while allowing code generation
- Useful for both regular and NIST projects

PHI DETECTION (NIST Projects):
- Automatically detects Protected Health Information columns
- Identifies: names, dates of birth, SSNs, addresses, phone numbers, etc.
- Redacts PHI columns before storage
- Shows compliance review modal before confirming upload
- Original data is never stored - only redacted versions

DATA REDACTION:
- PHI columns are replaced with "XXXX" tokens
- Column structure is preserved
- Data analysis can still work with redacted structure
- Redacted columns are clearly marked
- You can review redacted data before confirming

COMPLIANCE REVIEW:
- Shows preview of redacted data
- Highlights which columns were redacted
- Shows data summary (rows, columns)
- You can edit redaction settings before confirming
- Original data is discarded after redaction

DATA STORAGE:
- Regular projects: Data stored as uploaded (or randomized if privacy mode on)
- NIST projects: Only redacted data is stored
- Original sensitive data is never persisted
- All data encrypted in transit and at rest

AUDIT TRAIL (NIST Projects):
- All uploads are logged with timestamps
- AI interactions are tracked
- Access to projects is recorded
- Compliance reporting support

                           QUICK REFERENCE
================================================================================

KEYBOARD SHORTCUTS:
- Run Code: Click "Run" button or use keyboard shortcut (if configured)
- Save Version: Click "Save Version" button
- Toggle Privacy Mode: Use privacy toggle in upload panel
- Switch AI Mode: Use mode selector in chat box

COMMON WORKFLOWS:

1. STARTING A NEW PROJECT:
   - Log in → Dashboard → New Project → Enter name/description → Choose NIST or
     Regular → Open workspace

2. UPLOADING DATA:
   - Open workspace → Click upload → Select CSV files → Review (NIST: check
     redaction) → Confirm → Files appear in datasets panel

3. GENERATING CODE:
   - Type question in chat → Select AI mode → Choose datasets → Click send →
     AI returns code → Copy to editor → Run code

4. COLLABORATING:
   - Open project → Collaboration panel → Invite → Enter email/username →
     Select role → Send → Collaborator accepts → They gain access

5. SAVING VERSIONS:
   - Write/edit code → Click "Save Version" → Add description → Version saved
     → Can restore later from History

6. NIST COMPLIANCE WORKFLOW:
   - Create NIST project → Acknowledge compliance requirements → Upload data →
     Review PHI redaction → Generate context window → Use Ask Data mode for
     compliance-aware analysis

- Local storage required for some features

DATA LIMITS:
- File upload size: Depends on Supabase limits
- Project size: Database-dependent

- Version history: Unlimited snapshots

PERFORMANCE:
- Code execution: Depends on HuggingFace Space availability
- AI responses: Typically 10-40 seconds depending on complexity
- Real-time updates: Near-instant for collaboration features
- File processing: Depends on file size and complexity
